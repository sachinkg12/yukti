03

Application contribution

Yukti decides

A deterministic optimization core wrapped in explicit extension interfaces, an auditable API, and an optional AI-assistance layer.

∑

Optimize

milp-v1 jointly selects cards and allocates spend under card-count, annual-fee, linking, and piecewise reward-cap constraints.

◇

Value by goal

Cash, transferable points, and program currencies are converted using versioned USD-per-point values and goal-specific policies.

≡

Explain from evidence

Winner, cap, allocation, fee, assumption, and result facts are emitted as typed blocks with stable IDs and a graph digest.

Default optimization objective

maximize goal-valued rewards + credits − annual fees subject to portfolio, budget, allocation, linking, and cap-segment constraints
Catalog70 US cards · 19 reward currencies · 10 issuers
Strategies13 benchmarked optimizers plus 2 AHP variants in the runtime registry
StackJava 21 · OR-Tools CBC · React 18 · TypeScript
InterfacesOptimizer · RewardModel · ValuationModel · CatalogSource
AI
Optional means optional.

Goal interpretation and LLM narration are independently enabled. If credentials or switches are absent—or structured narration fails verification—the deterministic application path remains intact.

04

Research contribution

VerityGate verifies

A schema-level framework for deciding which LLM-generated claims are structurally licensed by a typed evidence graph.

Accepted paper GroundLM 2026 · EMNLP 2026 workshop

VERITYGATE: A Four-Gate Schema-Level Faithfulness Framework and Paired Benchmark for Grounded LLM Narrations over Structured Evidence

Sachin Gupta · Independent Researcher · San Jose, California, USA

Versioned code release ↗
Gate 1

Evidence existence

Reject citations whose stable evidence IDs are absent from the graph.

Gate 2

Entity allowlist

Reject declared cards or categories outside the graph-derived entity set.

Gate 3

Number binding

Reject declared numbers outside the graph's numeric allowlist and documented constants.

Gate 4

Claim-type rules

Require the evidence types needed by comparisons, fees, assumptions, and cap switches.

What transfers

A portable protocol

The claim/evidence schemas, stable citation pattern, graph digest, gate interface, and fail-closed rendering policy can be reused beyond rewards optimization.

What must be adapted

Domain semantics

Evidence builders, entity vocabularies, numeric policies, and type-specific rules encode domain knowledge and require new validation in another domain.

What is not claimed

Not a factuality oracle

A passing claim has structural support. The framework does not guarantee unrestricted prose entailment, complete citation, or correct upstream data.

Stable contracts

Inspect the boundary, not a black box

The public API reports optimization identity and verification metadata. The internal portable protocol binds claims to evidence by stable IDs and declared values.

  • Optional goalPrompt and optimizerId
  • Portfolio, allocations, and value breakdown
  • Evidence and claim digests, status, counts

Build and reproduce

Credential-free checks first

The application tests, verifier tests, and microbenchmark do not require model credentials. Paper-table reconciliation uses the separately downloaded supplement.

01Build and test the repository
./gradlew test --no-daemon
02Run the Yukti application locally
./gradlew :yukti-api:runServer
cd yukti-web && npm install && npm run dev
03Run the VerityGate verifier microbenchmark
./gradlew :yukti-bench:runVerifierMicroBench --no-daemon
04Reconcile paper tables from the supplement
python3 scripts/eval/reconcile_veritygate_results.py \
  --artifact-root /path/to/veritygate-groundlm-2026
